### Codebase Quality & Safety Audit

Perform a targeted code-quality audit across the active codebase under the categories below.

#### Project Context
- The codebase is Remixml: pure JavaScript (no TypeScript), zero runtime dependencies.
- It must run in modern browsers (and Node) on ES2018+: no Node.js-only globals, no host APIs accessed without `typeof` feature guards.
- The source of truth is `remixml.master.js`; `remixml.js` and `remixml.min.js` are generated by `./prepfiles`.

#### Audit Directives

0. **Look at the most recent audit**
   - Skip files or functions that were fully scanned in the last audit and have no related changes since.
1. **Inline Single-Use Functions**
   - Identify functions called and referenced exactly once, by direct invocation (i.e. fn()), and not referenced via a function pointer (this prevents static lambdas from being inlined again).
   - **Either:** the invocation is in the same module as the definition and the function is not exported, **or:** the invocation is in a different module AND the function body references at most one identifier from its own module.
   - Inline the function body at the invocation.
   - **Constraint:** Only perform this move if it does NOT result in the creation of an inline arrow function.
   - Delete the definition of the function you just inlined.

2. **Extract Static Lambda Functions**
   - Identify lambda functions which do not reference variables from the directly surrounding closure.
   - Define the function outside the current closure (as high up as possible).
   - Replace the lambda definition by a named reference to the newly defined function.

3. **Call-Site Consolidation & Function Encapsulation**
   - Identify repetitive boilerplate surrounding identical function calls.
   - Refactor by moving surrounding setup/teardown logic into the called function itself.
   - **Constraint:** Only perform this move if it reduces total duplicate code across multiple call sites. Do NOT create single-use wrapper functions or shift code around without net consolidation.

4. **DRY Extraction**
   - Identify near-identical or duplicated logic blocks.
   - Extract shared logic into clear, parameterised helper functions.
   - Ensure parameter signatures remain clean and intent-revealing.

5. **Dead Code Elimination**
   - Remove all unreferenced variables, functions and imports.

6. **Defensive Audit (Bugs, Races, Leaks)**
   - Audit for memory/resource leaks, race conditions, uncaught exceptions, and potential runtime crashes.
   - Enforce CONVENTIONS.md rules.
   - **Exclusions:** Ignore line-length restrictions, visual layout formatting, and staircase comment styling.

7. **Browser & Environment Compatibility**
   - Flag Node.js-only globals (`process`, `Buffer`, `fs`, runtime `require`) in code that must run in browsers.
   - Flag syntax or APIs newer than ES2018 that would ship without Closure Compiler downleveling.
   - Flag unguarded host-object access (`document`, `window`) and undeclared/leaked globals.
   - Flag anything that would violate the zero-runtime-dependency core.

#### Output Requirements
- Summarise and number proposed structural changes briefly before editing.
- Omit all points from the list which are classified as no-fix-needed.
